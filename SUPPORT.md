# Support

## Before asking for help

1. Read the [README](README.md), [architecture](docs/ARCHITECTURE.md), and [security baseline](docs/SECURITY_BASELINE.md).
2. Search existing issues for the same behavior.
3. Reproduce the issue on a current checkout when possible.
4. Record the commit SHA, Python version, operating system, command, sanitized error output, and expected versus observed behavior.

## Where to ask

- **Bug reports:** use the [GitHub issue tracker](https://github.com/LloydCoder/AURONTRA/issues) and select the bug-report template.
- **Feature requests:** use the feature-request template and describe the use case, constraints, and acceptance criteria.
- **Security vulnerabilities:** follow [SECURITY.md](SECURITY.md); do not post them publicly.
- **Conduct concerns:** contact hello@tinlance.com as described in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## What support can and cannot promise

Aurontra is under active hardening and is not certified production-ready. No production SLA, guaranteed response time for general questions, or commercial support plan is declared in this repository.

Never include access tokens, private keys, production database dumps, customer-identifying information, or sensitive telemetry in a public issue. Redact logs and configuration before sharing them.
